# ADR 검토

ADR은 사용자가 직접 쓴다. 목표는 사용자가 왜 그 결정을 했는지 스스로 설명하도록 돕는 것이다.
에이전트는 빈 곳을 짚고 마지막에 글을 정리할 뿐, 초안을 대신 쓰거나 처음부터 뜯어고치지 않는다.
문서 구조는 `docs/adr/template.md`와 그 주석을 따른다.

## 1. 초안 확인

- 초안이 없으면 대신 쓰지 말고 사용자에게 초안을 요청한다.
- 사용자가 러프하게 쓴 것을 전제로 읽는다. 이 단계에서는 문장, 맞춤법, 서식을 지적하지 않는다.

## 2. 검토와 피드백

초안을 이 결정을 논의한 Claude Code 대화 세션과 대조한다. 그 논의가 현재 세션에 없으면 어느 세션인지 사용자에게 묻는다. 논의한 세션이 없으면 초안만으로 검토하고, 그 사실을 알린다.

이 단계에서는 초안을 수정하지 않고 아래 두 가지만 피드백한다.

누락과 논리
- 치명적인 것만 한 번에 최대 3개까지 짚는다. 없으면 없다고 말하고, 3개를 억지로 채우지 않는다.
  - 핵심 근거 누락: 대화에서 결정을 좌우한 근거가 초안에 없다.
  - 논리 오류·빈약: 근거와 결정이 이어지지 않거나 서로 모순된다.
- 무엇이 왜 문제인지 설명하고, 사용자가 답을 채울 수 있게 질문한다. 바로 넣을 수 있는 문장을 대신 써 주지 않는다.
- 사소한 누락은 짚지 않는다.

틀린 기술 내용
- 기술적으로 틀린 내용은 개수 제한 없이 모두, 누락·논리 피드백과 구분해 알린다.
- 무엇이 왜 틀렸고 올바른 내용은 무엇인지 설명한다. 확실하지 않으면 공식 문서나 repo에서 확인하고, 확인하지 못했으면 그렇다고 밝힌다.
- 고치는 것은 사용자가 한다.

## 3. 보완 확인

- 사용자가 보완해 오면 앞서 짚은 내용이 해소됐는지와, 보완하면서 틀린 기술 내용이 새로 생겼는지 확인한다. 새로운 누락을 계속 찾아내지 않는다.
- 사용자가 누락·논리 피드백을 반영하지 않기로 하면 다시 요구하지 않는다.
- 틀린 기술 내용이 남아 있으면 정리하기 전에 다시 알린다.

## 4. 정리

- 사용자가 보완을 마쳤다고 하면 문장, 순서, 서식을 사람이 읽기 편하게 다듬는다.
- 사용자가 적지 않은 근거, 선택지, 결론, 대가를 추가하지 않는다. 대화 세션에 있는 내용이라도 사용자가 초안에 적지 않았으면 넣지 않는다.
- 사용자가 적은 내용의 의미와 확신의 정도를 바꾸지 않는다. 내용을 빼야 할 것 같으면 빼지 말고 사용자에게 묻는다.
- 비어 있는 섹션은 지어내지 말고 사용자에게 묻는다.
- 내용을 채운 섹션의 템플릿 주석은 지운다.
- 정리한 전문과 초안에서 달라진 점을 보여주고, 사용자가 승인한 뒤에 파일에 반영한다.
