# 프로젝트 시작 동기

## 왜 이 프로젝트를 시작했는가

나는 현재 편의점에서 근무하며 소비기한 등록 및 폐기 업무를 직접 수행하고 있다.

편의점 POS에는 이미 `소비기한 등록` 기능이 존재한다.

처음에는 해당 기능을 사용하면 소비기한 관리를 충분히 할 수 있을 것이라고 생각했다.

하지만 실제 업무를 수행하면서 기존 기능이 **내가 일하는 방식과 잘 맞지 않는다**는 사실을 반복적으로 경험하게 되었다.

특히 소비기한 등록, 조회, 폐기 과정이 자연스럽게 이어지지 않았고, 등록한 소비기한 정보를 지속적으로 관리하기 어렵다는 문제가 있었다.

## 내가 실제로 일하는 방식

근무하는 과정에서 모든 상품의 소비기한을 미리 등록하는 경우는 거의 없었다.

대신 특정 품목의 `가장 임박한 소비기한`을 확인하고 관리하는 방식으로 업무를 수행했다.

해당 품목을 폐기한 이후에는 진열대에 남아 있는 다음 상품의 소비기한을 다시 확인하여 등록했다.

즉, 내가 실제로 수행하는 업무의 핵심은 **모든 소비기한을 저장하는 것이 아니라, 현재 관리해야 하는 소비기한을 놓치지 않는 것이었다.**

## 문제 의식

기존 POS는 `소비기한 등록` 기능을 제공하지만, 내가 관리 중인 소비기한을 지속적으로 추적하기에는 한계가 있었다.

특히 품목을 삭제하는 순간 해당 품목의 소비기한 정보가 사라졌고, 다음 소비기한을 이어서 관리하기 어려웠다.

그 결과 소비기한 등록 기능만으로는 현재 상태를 신뢰하기 어려웠고, 결국 진열대를 다시 확인하는 수작업이 반복되었다.

## 프로젝트 목표

이 프로젝트의 목적은 편의점 전체 재고 관리 시스템을 만드는 것이 아니다.

또한 발주, 판매 분석, 매출 관리 기능을 구현하는 것도 현재 목표가 아니다.

내가 우선적으로 해결하고 싶은 문제는 다음과 같다.

> "내가 현재 관리 중인 소비기한을 신뢰할 수 있는 형태로 지속적으로 추적할 수 있을까?"

본 프로젝트는 이 질문에 답하기 위한 최소한의 기능을 직접 설계하고 구현하는 과정이다.

문제 정의, DB 설계, 애플리케이션 개발, 인프라 구성 및 배포까지 전 과정을 직접 수행하며 문제를 해결해 보고자 한다.
