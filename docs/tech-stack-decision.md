# Tech Stack Decision

## 문서 목적

이 문서는 `Store-Expiration-Tracker`의 초기 기술 스택 선택 배경과 판단 기준을 정리한다.

목적은 아래와 같습니다.

1. 왜 현재 스택을 선택했는지 기록한다.
2. 이후 구현 중 기술 선택이 흔들릴 때 기준점으로 사용한다.
3. 프로젝트 목표와 기술 스택의 관계를 명확히 남긴다.

## 최종 결정

- Backend: `FastAPI`
- Frontend: `Vue`

## 프로젝트 목표

이 프로젝트의 주요 목적은 아래 두 가지이다.

1. 실제 편의점 운영 문제를 해결하는 애플리케이션을 만든다.
2. 인프라 엔지니어 관점에서 애플리케이션 배포 및 운영 경험을 쌓는다.

이 프로젝트는 애플리케이션 프레임워크를 깊게 학습하는 것을 주목적으로 두지 않는다.  
대신 실제 서비스 형태의 애플리케이션을 만들고, 이를 배포·운영·확장 경험으로 연결하는 데 의미를 둔다.

## 고려한 후보

### 1. Spring Boot + React

장점:

- 실무형 웹 애플리케이션 스택으로 보이기 쉽다.
- 백엔드와 프론트엔드가 분리된 구조를 연습할 수 있다.

보류 이유:

- 현재 프로젝트 규모 대비 구현 비용과 학습 비용이 크다.
- 프레임워크 심층 학습이 이번 프로젝트의 핵심 목표는 아니다.
- 인프라 엔지니어 관점에서는 프레임워크 학습보다 배포 구조와 운영 경험이 더 중요하다.

### 2. Django + Vue

장점:

- Python 생태계를 사용하면서도 기능이 많은 프레임워크를 활용할 수 있다.
- 인증, ORM, 관리자 페이지 같은 기본 기능을 빠르게 활용할 수 있다.

보류 이유:

- Django는 내부 운영자가 웹에서 데이터를 많이 수정하는 서비스에 특히 강하다.
- 예를 들어 상품, 사용자, 권한, 공지, 설정 같은 데이터를 관리 화면에서 자주 수정해야 하는 구조라면 Django의 장점이 크게 살아난다.
- 현재 프로젝트의 중심은 그런 관리용 백오피스보다, 메인 대시보드에서 `처리 대상 조회 -> 폐기 처리 -> 다음 소비기한 반영 또는 empty 적용`을 빠르게 이어가는 작업 흐름에 가깝다.
- 따라서 현재 단계에서는 Django의 대표 강점보다, API 중심 구조와 상태 전이 구현의 단순성이 더 중요하다.

### 3. Node.js + Vue

장점:

- 이미 배포 연습 경험이 있는 조합이다.
- 프론트엔드 진입 장벽이 상대적으로 낮다.

보류 이유:

- 나중에 데이터 분석 방향으로 확장할 때 Python 생태계와 다시 연결해야 할 가능성이 높다.
- 이번 프로젝트는 운영 데이터 축적과 이후 분석 확장을 고려하고 있어, 백엔드는 Python 쪽이 더 자연스럽다.

## 선택 이유

### 1. FastAPI는 현재 작업 흐름에 더 잘 맞는다

현재 프로젝트의 중심은 관리용 백오피스보다 현장 작업용 운영 화면에 가깝다.

- 메인 대시보드 중심 UI
- 상태 전이 중심 백엔드 로직
- 프론트엔드와 분리된 API 서버

FastAPI는 이런 구조를 가볍게 시작하기 좋고, 현재 MVP 범위에도 잘 맞다.

### 2. Python 기반이라 데이터 분석 확장성이 좋다

이 프로젝트는 단순한 CRUD 앱으로 끝나지 않고, 이후 아래 방향으로 확장될 수 있다.

- 최근 3개월 기준 상품별 폐기 수량 집계
- 자주 또는 많이 폐기되는 상품 식별
- 폐기 데이터를 바탕으로 발주 유지 여부 검토

이 방향은 Python 기반 백엔드와 잘 맞다.

### 3. Vue는 현재 목표 대비 부담이 낮다

Vue는 이미 간단한 배포 경험이 있고, 데이터 흐름도 어느 정도 이해하고 있는 상태다.

이번 프로젝트에서는 프론트엔드를 깊게 학습하기보다, 운영 화면을 무리 없이 구현하고 배포 구조를 경험하는 것이 더 중요하다.  
이 기준에서 Vue는 지나치게 무겁지 않으면서도 충분한 선택지다.

### 4. 인프라 학습 포인트를 살리기 좋다

이 프로젝트에서 중요한 것은 프레임워크 자체보다 아래 경험이다.

- API 서버 배포
- 프론트엔드 정적 빌드 배포
- DB 연결 및 운영
- 환경 변수 관리
- Reverse Proxy 구성
- Docker 기반 배포 구조

`FastAPI + Vue`는 이 구조를 분리해서 연습하기에 적절하다.

## 정리

이 프로젝트는 프레임워크 학습 프로젝트가 아니라, 실제 문제를 해결하는 애플리케이션을 만들고 이를 인프라·배포 경험으로 연결하는 프로젝트다.

이 기준에서 `FastAPI + Vue`는 아래 균형이 가장 좋다.

1. 현재 MVP를 무리 없이 구현할 수 있다.
2. 이후 배포와 운영 경험으로 확장하기 좋다.
3. 폐기 데이터 기반 분석 방향과도 잘 맞다.
