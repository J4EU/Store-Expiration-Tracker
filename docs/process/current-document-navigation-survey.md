# 현재 기준 문서와 역사 문서의 선 분류 및 탐색 경로 조사

## 조사 목적과 범위

이 문서는 Issue #39의 조사 결과다. 저장소의 루트 `README.md`와 `docs/`의 21개 문서, 총 22개를 문서가 수행하는 역할과 독자가 여는 목적으로 선 분류한다. 문서 이동·삭제·병합·재작성, README 탐색 구조 변경, Source of Truth 확정, 코드·실제 배포 검증은 이 조사에 포함하지 않는다.

## 판단 기준

아래 질문을 함께 사용했다.

1. 독자는 프로젝트 이해, 현재 구현·운영, 과거 결정 확인 중 언제 이 문서를 여는가?
2. 현재 구현·운영·문서 수정의 기준인가? 규칙 변경 시 가장 먼저 고쳐야 하는가?
3. 현재 정책의 설명인가, 그 정책이 만들어진 이유의 증거인가?
4. 읽지 않아도 현재 작업이 가능한가? 시간이 지나며 누적되는 기록인가, 현재 상태를 유지하도록 갱신되는 문서인가?

`핵심 / 현재 기준 후보`는 현재 작업에서 먼저 참고하거나 규칙 변경 시 우선 갱신할 문서다. `역사 / 근거 후보`는 결정을 재검토할 때 읽는 증거다. 두 성격이 실제로 함께 있으면 단정하지 않고 `혼합 / 판정 유보`로 둔다. 이는 Source of Truth 확정이 아니라 후속 판단을 위한 선 분류다.

## 전체 문서 선 분류

### [README](../../README.md)

- **역할 분류:** 혼합 / 판정 유보
- **독자가 여는 목적:** 프로젝트를 처음 이해하고, 현재 제공 기능과 로컬 실행의 출발점을 찾는다.
- **현재 기준 여부:** 부분적으로 그렇다. 빠른 실행과 현재 범위는 기준으로 쓰이지만 프로젝트 동기·상태 서술도 함께 있다.
- **역사적 근거 여부:** 그렇다. 프로젝트가 만들어진 배경과 진행 경위도 담는다.
- **가장 먼저 수정해야 하는 문서인지:** 기능 범위나 첫 실행 경로가 바뀔 때는 우선 후보지만, 세부 규칙의 최초 수정처로 단정할 수 없다.
- **판단 근거:** 소개, 실행, 범위, 현재 상태, 문서 안내가 한 문서에 공존한다.
- **혼합인 이유:** 현재 안내와 누적된 프로젝트 서사가 분리되어 있지 않다.

- **현재 기준 여부:** 직접 기준으로는 아니다.
- **역사적 근거 여부:** 그렇다.
- **가장 먼저 수정해야 하는 문서인지:** 검증 정책의 결정 경위를 갱신할 때 해당한다.
- **판단 근거:** 검증 실행 자체는 Runbook으로 분리했고, 이 문서는 Review와 이관 관계를 설명한다.

### [SPA fallback and routing policy](../deployment/issue-28-spa-fallback-routing-policy.md)

- **역할 분류:** 혼합 / 판정 유보
- **독자가 여는 목적:** SPA fallback, API 경로, 브라우저 URL의 현재 정책과 그 판단 배경을 함께 확인한다.
- **현재 기준 여부:** 그렇다. 현재 URL·API 경로 정책을 직접 설명한다.
- **역사적 근거 여부:** 그렇다. Issue에서 관찰한 현상과 선택 이유도 담는다.
- **가장 먼저 수정해야 하는 문서인지:** URL·fallback 정책 변경 시 우선 후보이나, 운영/개발 기준의 최종 위치는 미정이다.
- **판단 근거:** 정책 본문과 관찰·한계·후속 결정 조건이 결합돼 있다.
- **혼합인 이유:** 현재 정책과 Issue 기반 판단 근거를 분리하지 않는다.

### [배포 전 인증 검증 Runbook 초안](../deployment/pre-deploy-auth-runbook.md)

- **역할 분류:** 핵심 / 현재 기준 후보
- **독자가 여는 목적:** 배포 직전·직후 인증, 세션, reverse proxy를 실제 URL에서 검증한다.
- **현재 기준 여부:** 그렇다. 반복 가능한 실행 절차다.
- **역사적 근거 여부:** 아니다.
- **가장 먼저 수정해야 하는 문서인지:** 배포 검증 순서·명령·기록 항목이 바뀔 때 우선 수정한다.
- **판단 근거:** 사용 시점과 단계별 실행·실패 처리·기록 양식을 명시한다.

### [Project Workflow](project-workflow.md)

- **역할 분류:** 핵심 / 현재 기준 후보
- **독자가 여는 목적:** 브랜치, PR, `main` 병합 작업의 저장소 운영 규칙을 확인한다.
- **현재 기준 여부:** 그렇다.
- **역사적 근거 여부:** 일부 날짜 기록은 있으나 문서의 주 역할은 현재 규칙 설명이다.
- **가장 먼저 수정해야 하는 문서인지:** 저장소 작업·병합 정책이 바뀔 때 우선 수정한다.
- **판단 근거:** 반복 작업에서 참고할 운영 기준을 명시하고 현재 허용 규칙을 적는다.

## 후속 작업 후보

다음은 이 조사에서 실제 변경하지 않는 후속 작업 후보다.

1. 혼합 문서의 현재 규칙과 역사·계획 문단을 분리할 필요성과 우선순위를 판단한다.
2. 제품 범위·데이터 규칙·API·화면 규칙별 현재 기준 문서의 위치를 검토한다. 이는 Source of Truth 확정 작업으로 별도 범위가 필요하다.
3. README와 Documentation index에 독자 질문별 탐색 경로를 실제로 반영할지 검토한다.
4. Issue Review의 현행 결론을 현재 기준 문서에 반영하는 방식과, Review의 후속 현황 기록 방식을 정리한다.
5. Development·Deployment·Process 문서에도 같은 판단 기준을 적용해 수정 시점과 참조 관계를 확인한다.
