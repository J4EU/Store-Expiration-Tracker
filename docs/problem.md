# 문제 정의

## 배경

> 본 문서는 현재 편의점에서 실제로 수행 중인 소비기한 관리 업무를 기반으로 작성됨

아래 내용은 현재 수행 중인 소비기한 등록 및 폐기 업무의 사용 경험과 관찰을 바탕으로 정리하였다.

## 기존 편의점 소비기한 등록

POS에 `소비기한 등록 기능`이 존재하지만 다음과 같은 문제점이 있다.

- 실제 현장에서는 사용 빈도가 낮다.
- `소비기한 기간조회`: 기본값이 `오늘-내일`로 되어있다.
- 조회 기간은 사용자가 자유롭게 지정할 수 있으나, 한 번에 조회 가능한 기간이 최대 7일로 제한되어 있다.

### 등록 방법

1. 상품 바코드 스캔
2. 소비기한 선택 (캘린더 방식, 숫자 입력이 아니라 캘린더에서 터치해야 함)
3. 시간 항목 입력 (사용하지 않는 기능, `placeholder`가 없고 사용 방법이 명확하지 않음)
4. 등록 수량 입력
5. `등록` 버튼 터치

입력 도중 마지막 `등록` 버튼을 누르지 않은 상태에서 다른 날짜를 조회하면, 앞에서 입력한 정보가 모두 사라진다. 등록 과정이 중간에 끊기기 쉽고 다시 입력해야 하는 부담이 있다.

또한 POS에는 상품별 현재 상태를 유지하는 개념이 부족하다. 소비기한이 없는 상태를 별도로 관리하지 못하고, 등록된 정보가 사라지면 그 상품이 다시 확인이 필요한 대상이라는 사실도 함께 사라진다.

## 소비기한 점검 및 폐기

### 실제 사용 흐름

실제 업무 흐름은 대체로 `조회 -> 품목 확인 -> 폐기 -> 재진입 -> 삭제 또는 갱신 -> 반복` 순서로 이루어진다.

1. 근무자가 소비기한 관리가 필요하다고 판단했을 때 POS의 `소비기한 등록` 메뉴에 진입한다.
2. 조회 기간이 `오늘-내일`로 지정된 상태에서 `조회` 버튼을 터치한다.
3. 오늘, 내일 등록된 소비기한 품목 리스트가 나타난다.
4. 오늘까지인 품목을 확인하고, 해당 품목을 가져온다.
5. POS `메인 화면`으로 돌아가 폐기 메뉴에 진입한다.
6. 폐기를 진행한 후, 다시 `소비기한 등록` 메뉴로 진입한다.
7. `조회` 버튼을 터치한 후, 방금 처리한 품목을 리스트에서 `삭제`한다.
8. 다음에 등록할 상품이 있으면 소비기한을 다시 등록하고, 없으면 기존 정보를 삭제한다.
9. 이후 오늘 날짜의 폐기 품목이 존재한다면 위의 과정을 반복한다.

#### 품목 리스트

- 품목 리스트는 날짜별로 정렬되지 않는 문제가 존재한다.
- 품목 리스트에는 존재하지만 실제 진열 상품의 소비기한이 다를 경우, 기존 등록 정보를 삭제하고 다시 등록해야 한다.

## 핵심 문제점

> 현재 시스템에서는 다음에 등록할 상품이 없는 상태에서 품목을 삭제하면, 소비기한 정보뿐 아니라 그 상품이 관리 대상이었다는 사실 자체도 함께 사라진다.

- 현재 시스템은 소비기한 정보를 등록하고 조회할 수는 있지만, 상품별 소비기한 상태를 지속적으로 유지하기 어렵다.
- 어떤 상품에 다음 소비기한이 아직 등록되지 않은 경우, 이를 `소비기한이 비어 있는 상태`로 남겨두고 추적할 수 없다.
- 그 결과 근무자는 어떤 상품의 소비기한이 비어 있는지 알 수 없고, "내가 어떤 상품을 삭제했지?", "어떤 상품을 다시 기입해야 하지?"를 기억에 의존하게 된다.
- 결국 진열대 전체를 다시 확인하는 수작업과 인지 소모가 반복된다.
- 문제의 핵심은 단순히 `다음 소비기한 등록의 불편함`이 아니라, `상품별 관리 상태가 시스템에 남지 않는다`는 점이다.

## 업무 제약 사항

소비기한 검사는 모든 상품의 모든 소비기한을 미리 등록하는 방식으로 수행하지 않는다.

근무자는 일반적으로 상품별로 가장 임박한 소비기한만 등록하며, 해당 품목을 폐기한 후 다음 소비기한을 다시 확인하여 등록한다.

또한 한 번이라도 등록한 상품이라면, 이후에는 소비기한 값이 존재하거나 비어 있는 상태로라도 시스템에 남아 있어야 한다.

처음 등록 시점에는 소비기한을 함께 입력할 수도 있고, 상품만 먼저 등록한 뒤 소비기한을 나중에 채울 수도 있어야 한다.

이때 `소비기한이 비어 있음`은 오류나 누락이 아니라, 현재 다시 확인이 필요한 정상적인 관리 상태로 취급해야 한다.

따라서 시스템은 품목별 모든 소비기한을 저장하는 방식보다, 상품 정보가 사라지지 않은 상태에서 현재 관리 중인 소비기한과 소비기한이 비어 있는 상품을 함께 추적할 수 있는 구조에 최적화되어야 한다.
