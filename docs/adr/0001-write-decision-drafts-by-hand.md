# ADR-0001: 앞으로 결정 문서 초안은 직접 적는다

- 상태: 승인됨
- 날짜: 2026-11-24

## 상황

기존 `docs/decisions`의 문서들은 Claude Code 세션에서의 대화를 기반으로 AI가 작성하고, 내가 검토하고 승인하는 방식으로 운영했다.

이 방식은 작업 속도는 빠르지만, 내가 문서를 제대로 이해했다는 확신이 들지 않았다. 특히, 어떤 결정 문서를 남겼는지 금방 기억에서 사라지기도 했다.

## 선택지

### 1. 기존의 방식과 템플릿을 유지하고, 문서를 읽기 쉽게 수정한다

`docs/decisions` 문서들의 섹션명과 내용을 내가 읽기 쉬운 수준으로 수정한다.

- 장점: 문서만 수정하면 되고, 앞으로도 문서 작성에 대한 부담이 크지 않다.
- 단점: 기존 방식으로 계속 문서를 생성할수록 이해하기 어려운 문서들, 기억하지 못하는 문서들이 더 많아질 수 있다.

### 2. 새로운 템플릿을 기반으로 초안을 직접 적는다

앞으로 쌓을 결정 문서는 나 혼자 적어보고, AI의 피드백과 직접 수정을 거쳐, 마지막엔 AI가 최종 문서 형태로 다듬게 한다. 초안을 직접 작성하기 위해, 템플릿은 내 수준에 맞춰 부담 없이 작성할 수 있는 쉬운 형태로 제작한다.

- 장점: 해당 결정을 제대로 이해하고 부족한 부분은 다시 공부하는 과정을 거쳐, 문서의 내용을 보다 확실하게 이해할 수 있다.
- 단점: 결정 문서를 작성할 때마다 초기 수동 작성이 요구되어, 시간 효율은 선택지 1보다 나쁘다.

## 결정

선택지 2로 결정한다.

결정 문서는 미래의 내가 '왜 이렇게 구현됐지?', '언제 이런 결정을 했지?'를 추적하기 위해 필요하다. 그러나 내가 이해하지 못한 문서가 늘어난다면, 특정 주제의 문서를 찾고 싶을 때 어떤 문서가 있었는지 기억하기 어렵고, 찾더라도 그 내용을 이해하기 위해 다시 공부해야 할 수 있다.

작업의 속도도 중요하지만, AI와 구현하면서 내가 어떤 결정을 했는지 스스로 적어보고, 놓친 점이나 제대로 이해하지 못한 개념이 있는지 확인하고, 부족한 부분을 다시 학습하기 위해 선택했다.

추가적으로, 기존 결정 문서들은 새로운 ADR 템플릿에 맞춰 수정하기 전까진 현재의 파일 경로와 상태를 유지한다.

## 대가

- ADR 문서를 작성할 때 시간 소요가 클 수 있다. 작업 가능한 시간이 많지 않아서, 하루 전체를 ADR 문서 작성과 수정에 쓸 수 있다.
- ADR 작성이 프로젝트 작업에 대한 진입 장벽을 높일 경우, 이 문서와 `.claude/skills/review-adr/*`을 재검토한다.
