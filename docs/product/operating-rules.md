# Product Operating Rules

이 문서는 상품, 현재 소비기한, 폐기, 아카이브가 현재 Product에서 어떤 의미로 동작하는지 설명한다. 정확한 schema, endpoint, payload, validation, 화면 interaction은 코드가 기준이다.

## 상품과 현재 소비기한

- 상품은 물리적으로 삭제하지 않고 `active` 또는 `archived`로 관리한다.
- 각 상품은 현재 소비기한 상태를 하나만 가진다.
- 현재 소비기한에 날짜가 있으면 그 날짜를 추적 중인 상태다.
- `expiration_date = NULL`은 오류나 단순 누락이 아니라, 현재 소비기한을 다시 확인해야 하는 정상적인 `미확인` 관리 상태다.
- 지난 날짜, 당일, 임박 같은 날짜 기반 분류는 별도 상태값으로 저장하지 않고 조회 시 계산한다.
- 상품은 바코드로 먼저 찾고, 등록되지 않은 바코드일 때만 신규 등록한다.

`tracked`와 `empty`는 현재 `expiration_date`의 `NULL / NOT NULL`과 같은 의미이므로 별도 state로 중복 저장하지 않는다. 날짜 유무만으로 표현할 수 없는 실제 업무 상태가 생기면 별도 state 도입을 재검토한다.

바코드 우선 흐름은 배포 전 로컬에서 상품을 반복해 선등록할 때의 피로를 줄이기 위해 선택했다. `scan + Enter`가 즉시 조회로 이어지게 하되, 키보드로 입력하는 경우를 위해 조회 버튼을 fallback으로 유지한다.

## 운영 화면의 처리 대상

운영 화면은 소비기한이 있는 active 상품과 `미확인` active 상품을 구분해 보여준다.

- `오늘 처리`에는 지난 날짜와 당일 만료 상품을 포함한다.
- `유제품` 카테고리의 다음 날 만료 상품도 `오늘 처리`에 포함한다.
- 현재 운영상 카테고리는 `미선택`과 `유제품`을 사용한다. 이 값 제한은 DB invariant가 아니라 backend validation의 현재 규칙이다.

## 실제 폐기

실제 폐기는 남아 있는 재고를 실제로 폐기한 사건이다.

- 실제 폐기 수량은 0보다 커야 한다.
- 실제 폐기는 폐기 수량 이력을 남긴다.
- 처리 뒤 현재 소비기한은 `미확인` 상태로 전환된다.

## 폐기 없음

`폐기 없음`은 소비기한을 확인했지만 이미 판매되어 실제로 폐기할 재고가 없는 사건이다.

- 실제 폐기 이력을 만들지 않는다.
- 다음 소비기한을 바로 확인할 수 있으면 그 날짜로 갱신한다.
- 바로 입력하지 않으면 현재 소비기한은 `미확인` 상태로 전환된다.

따라서 실제 폐기와 폐기 없음은 비슷한 후속 관리 흐름을 가질 수 있어도, 남기는 운영 결과의 의미는 다르다.

`폐기 없음` 뒤에 다음 소비기한 입력을 바로 여는 이유는 이 시점에 운영자가 다음 상품을 이미 확인하고 있을 가능성이 높아 현장 동작과 자연스럽게 이어지기 때문이다.

소비기한 수정은 정상적인 폐기나 상태 전이를 대체하는 수단이 아니다. 수정 액션이 핵심 액션처럼 노출되면 실제 폐기 이력을 남기지 않고 날짜만 바꾸는 흐름을 유도할 수 있으므로, 핵심 처리 액션과 분리해 `더 보기`에 둔다.

## 아카이브와 복구

아카이브는 더 이상 현재 소비기한을 추적하지 않을 상품을 운영자가 수동으로 결정하는 상태 전환이다.

- 아카이브하면 상품은 보존되지만 기본 운영 목록에서는 제외된다.
- 아카이브하면 현재 소비기한은 `미확인` 상태로 둔다.
- 복구하면 상품은 다시 active가 되고, 현재 소비기한은 `미확인` 상태로 둔다.
- 기존 실제 폐기 이력은 아카이브와 복구 뒤에도 유지된다.

왜 삭제 대신 보존하고 자동 아카이브를 선택하지 않는지는 [Product Retention and Archiving](../decisions/product-retention-and-archiving.md)를 따른다. 실제 폐기 이력의 범위는 [Discard History Scope](../decisions/discard-history-scope.md)를 따른다.
