# Product Overview

## 이 제품은 무엇을 해결하는가

Store-Expiration-Tracker는 한 번 관리 대상으로 등록한 상품의 소비기한 관리 상태가 끊기지 않게 유지되는 단일 점포 운영 도구다.

기존 POS에서는 다음 소비기한이 없는 상품의 정보를 삭제하면 날짜뿐 아니라, 그 상품을 다시 확인해야 한다는 관리 맥락도 함께 사라진다. 그 결과 운영자는 기억에 의존하거나 진열대를 다시 전수 확인해야 한다.

이 제품은 소비기한 날짜를 단순 저장하는 데 그치지 않고, 관리 대상 상품이 현재 소비기한을 확인한 상태인지 다시 확인해야 하는 상태인지를 계속 남긴다.

## 사용자와 현재 범위

현재 정책적 범위는 소비기한 등록과 폐기 업무를 직접 수행하는 단일 점포의 단일 운영자다. 이는 현재 Product scope이며 DB가 강제하는 구조적 제약은 아니다.

현재 제품은 다음을 다룬다.

- 바코드 기반 상품 조회와 필요한 경우의 신규 등록
- 상품별 현재 소비기한 상태 추적
- 오늘 처리 대상과 다시 확인이 필요한 상품의 운영 화면
- 실제 폐기와 폐기 없음의 구분
- 상품 아카이브와 복구
- 실제 폐기 수량의 누적 저장

다음은 현재 범위 밖이다.

- 편의점 전체 재고 관리
- 발주 시스템
- 매출 관리와 판매 분석
- 분석 조회·집계 화면 또는 API
- 멀티 점포
- 다중 사용자 및 역할 기반 권한 관리

현재 운영자 접근 제어의 상세 정책은 [Operator Session Policy](../decisions/operator-session-policy.md)를 따른다.

## 핵심 운영 흐름

운영자는 바코드로 상품을 먼저 찾는다. 기존 상품이면 현재 소비기한을 갱신하고, 등록되지 않은 바코드일 때만 상품을 새로 등록한다.

운영 화면에서는 오늘 처리할 상품과 현재 소비기한을 다시 확인해야 하는 상품을 확인한다. 처리 대상은 실제 폐기, 폐기 없음, 또는 아카이브 중 현재 상황에 맞는 결과로 이어진다. 각 결과의 상태 의미와 전이는 [Operating Rules](operating-rules.md)에 둔다.

## 폐기 데이터의 목적

실제 폐기 수량을 누적하는 목적은 일반적인 BI나 통계 기능을 제공하는 것이 아니다. 반복되는 실제 폐기 수량을 통해 해당 상품의 현재 발주량이나 취급 유지 여부를 다시 검토할 근거를 남기는 데 있다.

현재 제품에는 이 데이터를 조회·집계하는 분석 API나 분석 화면이 없다. 현재 `dashboard`는 분석 dashboard가 아니라 운영 처리 화면이다.
